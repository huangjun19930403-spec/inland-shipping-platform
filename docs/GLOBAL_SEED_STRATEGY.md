# 全局 Seed 与本地验证数据策略

## 1. Seed 分层

### 基础 seed

本地、测试、生产初始化都可使用：

- 字典
- 编码序列
- 系统角色
- 菜单
- 系统配置
- 行政区划
- 货品分类
- 货品类型
- 标准货品
- 标准货品别名
- 运输方式
- 船舶类型
- 节点类型
- 通航约束类型

基础 seed 原则：

- 必须幂等。
- 不带测试语义。
- 不依赖 E2E 专用编码。
- 不生成大量业务样例。
- 可支撑系统启动、权限、菜单、字典、基础筛选和最小业务录入。

### 演示 seed

本地和演示环境使用：

- 业务区域
- 运输节点
- 通航约束点
- 船舶样例
- 货源样例
- 航线样例
- 分析统计样例

演示 seed 原则：

- 使用真实风格命名，不全叫“测试XXX”。
- 覆盖近 30 天业务时间范围。
- 覆盖苏州、无锡、太仓、芜湖、宣城、扬州、上海等核心区域。
- 能支撑列表、详情、筛选、图表、地图、流向、热力、明细穿透本地验证。

### E2E seed

自动化测试使用：

- E2E_ROUTE_MAP
- E2E_ROUTE_PLAN_MAP
- E2E_CONSTRAINT_BRIDGE
- 其他 E2E 专用数据

E2E seed 原则：

- 编码稳定。
- 数据量小。
- 与演示数据隔离。
- 只服务自动化测试定位和断言。
- 不作为产品演示数据，不污染业务看板。

## 2. 当前 seed 问题

- E2E 数据和演示数据混用，当前 `seed_system_init` 会执行航线 E2E seed。
- 演示数据不足，无法支撑真实本地验证。
- 当前标准货品 seed 只有 9 个左右，远不足以覆盖真实货品筛选、别名和分析。
- 如果没有 30+ 标准货品、30+ 节点、50+ 船舶、100+ 货源，本地无法验证。
- 全是“测试XXX”会导致产品验证不真实，无法判断用户是否能理解页面信息。
- 通航约束点当前偏 E2E 样例，缺少非 E2E 演示数据。
- 船舶、货源、分析统计样例缺口较大，导致分析页和数据总览无法产品化。
- 货品分类/类型应留在基础 seed，不应因为有 seed 就暴露成普通业务一级页面。

## 3. 第 1 轮 seed 重构目标

### 行政区划

至少覆盖：

- 江苏省：苏州、无锡、常州、南通、镇江、泰州、扬州、南京
- 安徽省：芜湖、宣城、马鞍山
- 上海市
- 浙江部分城市

验收：

- clean DB 后可在行政区划选择、城市筛选、区域配置、节点归属中使用。
- 城市编码稳定，供货源、船舶、分析、航线 seed 引用。

### 货品

分类：

- 建材
- 能源
- 矿产
- 粮食
- 化工
- 钢材
- 集装箱
- 其他散货

类型：

- 砂石骨料
- 水泥熟料
- 煤炭
- 矿粉
- 钢材
- 粮食
- 化工品
- 淤泥/泥浆

标准货品至少 30 个：

- 黄砂
- 石子
- 碎石
- 机制砂
- 水泥熟料
- 粉煤灰
- 煤炭
- 焦炭
- 矿粉
- 铁矿石
- 石灰石
- 石膏
- 钢材
- 卷钢
- 玉米
- 大豆
- 淤泥
- 工程渣土
- 集装箱

补充方向：

- 河砂
- 炉渣
- 石粉
- 水泥
- 熟料粉
- 钢坯
- 螺纹钢
- 热卷
- 小麦
- 豆粕
- 砂浆
- 化工原料

别名：

- 黄沙 -> 黄砂
- 石料 -> 石子
- 煤 -> 煤炭
- 矿渣粉 -> 矿粉

验收：

- 标准货品 >= 30。
- 货品别名 >= 50。
- 标准货品列表可按分类、类型、关键词筛选。
- 货源 seed 能引用标准货品，而不是只写自由文本。

### 业务区域

至少 6 个：

- 苏州水运区域
- 无锡建材区域
- 太仓港区
- 长江下游区域
- 皖南水运区域
- 上海港航区域

验收：

- 每个区域有城市归属或边界示例。
- 可被运输节点、船舶分析、货源分析、航线方案引用。

### 运输节点

至少 30 个真实风格节点：

- 苏州吴中码头
- 太仓港城港区
- 无锡经开建材码头
- 常州金坛码头
- 芜湖港散货码头
- 宣城水阳江码头
- 扬州高邮湖作业点
- 镇江大港作业区
- 南京龙潭港区

补充方向：

- 苏州相城作业点
- 苏州工业园区港区
- 江阴临港作业区
- 张家港保税港区
- 南通通州湾作业区
- 泰州高港作业区
- 马鞍山港区
- 上海外高桥港区
- 嘉兴内河码头
- 湖州南浔作业点

验收：

- 运输节点 >= 30。
- 有经纬度、城市、节点类型、业务类别。
- 地图页面可以显示多个节点，不再只有 E2E 点。

### 通航约束点

演示数据至少 8 个，不全是 E2E：

- 京杭运河某船闸
- 苏州某桥梁净空限制
- 无锡某浅滩水深限制
- 长江下游限航点

补充方向：

- 太仓港区限航点
- 镇江桥梁净空限制
- 高邮湖季节性浅水点
- 水阳江通航限制点

验收：

- 通航约束点 >= 8。
- E2E 约束点仍独立稳定。
- 演示约束点可被地图、航线方案和分析说明引用。

### 船舶

至少 50 条：

- 不全叫测试船
- 有船型
- 有 MMSI
- 有载重吨
- 有建造年份
- 有船籍港
- 有经营状态
- 有部分证书样例

验收：

- 船舶档案 >= 50。
- 船型、载重吨、建造年份、船籍港、经营状态分布合理。
- 船舶列表、详情、画像、证书、分析看板有可验证数据。

### 货源

至少 100 条：

- 覆盖近 30 天
- 覆盖苏州、无锡、太仓、芜湖、宣城、扬州、上海
- 货品覆盖砂石、煤炭、水泥熟料、淤泥、钢材
- 来源包括手工、微信、TMS
- 状态包括正式、过期、待确认
- 价格和吨位合理

验收：

- 正式货源 >= 100。
- 列表可按日期、城市、货品、状态、来源筛选。
- 能生成货源日趋势、城市统计、流向统计、货品统计、渠道统计。

### 分析统计

基于货源和船舶演示数据生成：

- 货源日趋势
- 城市统计
- 流向统计
- 货品统计
- 渠道统计
- 船舶城市统计
- 船舶流向统计
- 分析任务记录

验收：

- 统计覆盖近 30 天。
- 分析任务记录能说明生成时间、状态、影响行数。
- 分析页不依赖人工临时造数据。

## 4. 本地验证标准

clean DB 后：

```bash
alembic upgrade head
python -m scripts.seed_system_init
```

必须满足：

- 标准货品 >= 30
- 货品别名 >= 50
- 业务区域 >= 6
- 运输节点 >= 30
- 通航约束点 >= 8
- 船舶档案 >= 50
- 正式货源 >= 100
- 货源分析统计覆盖近 30 天
- 船舶分析统计覆盖近 30 天
- 页面不再全是“测试XXX”

第 1 轮建议新增只读验证脚本或命令输出：

- 输出基础 seed 计数。
- 输出演示 seed 计数。
- 输出 E2E seed 计数。
- 输出是否存在过多“测试”命名。
- 输出分析统计日期范围。

本地验证通过后，后续第 2-8 轮才能进入页面产品化和接口重构。
