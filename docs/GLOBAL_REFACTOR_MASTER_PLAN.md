# 全局产品化重构总控计划

## 1. 为什么暂停局部 4E

当前不继续做路径节点编辑器。阶段 4B-4D 已经把航线模块从旧航段操作推进到路径节点串、航段生成结果、地图展示的基础能力，但继续深做 4E 会把项目重新带回“一个接口一个页面”的局部迭代惯性。

当前更需要全局收敛。现有后端已经形成系统、字典、地址、货品、船舶、货源、航线、分析、审核等多个模型域，但前端菜单、页面形态、seed 数据和分析门面还没有形成统一产品结构。局部航线功能继续做，会掩盖分析、seed、组件、菜单、货源、船舶等全局问题。

4E 暂停不是否定航线方向，而是把航线第 8 轮统一纳入“节点串 -> 自动生成航段 -> geometry -> 约束影响 -> 可行性判断”的完整产品链路，避免先把编辑器做深，再反向补全缺失的基础数据、分析能力和组件体系。

## 2. 当前项目最大问题

- 后端已有很多模型，但业务域边界还需要重新收敛，部分后台对象被当成业务主对象暴露。
- 前端页面偏接口后台，很多页面直接对应 CRUD 接口，而不是用户任务。
- 分析模块偏表格查询，当前主要展示分页统计表，不像平台核心门面。
- seed 不足以支撑真实本地验证，现有标准货品数量有限，船舶、货源、分析统计演示数据不足。
- 菜单暴露了太多后台对象，例如货品分类、货品类型、船舶导入批次。
- 货品分类/类型、船舶导入批次不应该作为一级业务页面。
- 工作台应该改为数据总览，展示业务指标、趋势、地图和待办，而不是只展示用户上下文。
- E2E 数据和演示数据存在混用倾向，例如航线 E2E seed 被纳入统一初始化链。
- 分析接口当前偏明细分页，缺少面向图表和地图的聚合 API。
- 前端组件体系还不够产品化，页面结构、图表卡片、地图面板、指标卡、筛选区需要统一。

## 3. 全局重构原则

1. 不再按接口直接生成页面。
2. 不再新增低价值工作台式页面。
3. 货品分类/类型不作为业务一级页面。
4. 船舶导入批次不作为业务页面。
5. 分析页面必须图表化、地图化。
6. seed 必须支撑本地真实验证。
7. 前端页面必须以用户任务为中心。
8. 后端表结构不支撑业务时允许重构表结构。
9. 删除无价值旧页面和旧菜单，不做兼容式堆叠。
10. E2E 数据、演示数据、基础数据必须分层。

## 4. 全局执行轮次

### 第 0 轮：总控定稿

目标：锁定边界，不改业务代码。

本轮只新增总控文档，明确后续 8 轮怎么做、哪些页面删除/隐藏、哪些模块产品化、seed 如何分层、前后端如何配合。

### 第 1 轮：Seed 与本地验证数据重构

目标：clean DB 后具备真实可验证数据。

把 seed 拆为基础 seed、演示 seed、E2E seed。补足行政区划、标准货品、货品别名、业务区域、运输节点、通航约束点、船舶、货源、分析统计样例。`python -m scripts.seed_system_init` 只承担基础初始化和必要本地验证入口，不再把 E2E 数据混入普通演示数据。

### 第 2 轮：前端组件体系基建

目标：建立 PageHeader、FilterPanel、MetricCard、ChartCard、MapPanel、DataTableCard 等通用组件。

先统一页面骨架、筛选区、表格卡片、指标卡、图表卡片、地图面板、状态标签、空状态、详情 tabs，再进入大规模页面产品化，避免每个模块重复造页面结构。

### 第 3 轮：菜单与页面结构收敛

目标：删除低价值页面入口，重组菜单为产品模块。

删除/隐藏货品分类、货品类型、船舶导入批次等后台对象入口。工作台改为数据总览。菜单按数据标准化、货源数据、船舶数据、航线方案、数据分析、审核治理、系统管理重组。

### 第 4 轮：分析模块产品化重构

目标：货源分析、船舶分析从表格页升级为 ECharts + 地图 + 指标卡。

分析模块成为平台核心门面。后端提供 overview、trend、rank、flow map、heatmap 等聚合接口；前端提供指标卡、趋势图、排行图、分布图、流向地图、热力地图、明细穿透。

### 第 5 轮：基础数据模块产品化重构

目标：地址、区域、节点、约束点、标准货品成为标准化底座。

地址与区域、运输节点、通航约束点、标准货品围绕“标准化匹配和业务能力档案”重构。分类/类型只作为筛选维度和 seed 数据，不做业务一级页面。

### 第 6 轮：货源链路产品化重构

目标：采集 -> AI解析 -> 候选 -> 确认 -> 正式货源 -> 分析。

正式货源列表保留并升级；新增采集与解析、候选确认、质量看板方向。后端如果现有 `freight` 表不能支撑采集链路，应新增 ingest/raw/clue/candidate/confirm/quality/duplicate 等链路表。

### 第 7 轮：船舶画像产品化重构

目标：船舶档案、画像、证书、AIS、分析；删除导入批次业务页面。

船舶导入作为船舶列表动作，返回结果摘要和错误明细下载，不作为业务一级对象。船舶画像补充质量分、区域统计、流向统计、热力、运力分布、船龄分布等分析能力。

### 第 8 轮：航线方案产品化重构

目标：节点串 -> 自动生成航段 -> geometry -> 约束影响 -> 可行性判断。

承接 4B-4D 成果，统一重构航线列表、路径方案、节点串、航段生成、地图展示、约束影响、可行性判断。旧航段主操作降级为生成结果和调试信息。

## 6. 当前必须删除/隐藏的对象清单

| 对象 | 处理方式 | 原因 |
|---|---|---|
| 货品分类页面 | 菜单删除/隐藏 | 分类是基础 seed，不是业务页面 |
| 货品类型页面 | 菜单删除/隐藏 | 类型是基础 seed，不是业务页面 |
| 船舶导入批次页面 | 删除/隐藏 | 导入应作为船舶列表动作 |
| 船舶导入批次详情页 | 删除/隐藏 | 不作为业务页面 |
| 系统工作台 | 改为数据总览 | 当前只展示用户上下文，业务价值不足 |
| 表格式分析页 | 重构 | 需要图表和地图 |
| 航线旧航段主操作 | 降级 | 后续由节点串生成航段 |

补充建议项：

| 对象 | 处理方式 | 原因 |
|---|---|---|
| 字典管理普通业务入口 | 降级到系统管理/管理员入口 | 字典主要由 seed 预制，业务人员不应频繁维护 |
| 编码序列普通业务入口 | 降级到系统管理/管理员入口 | 编码序列属于平台治理能力 |
| `/route/plans` 独立菜单 | 保持隐藏或删除菜单 | 方案入口应归并到航线列表和详情 |

## 7. 后续执行顺序

先第 0 轮，再第 1 轮。

第 1 轮必须优先，因为 seed 不足会导致后续页面无法验证。没有真实风格的货品、节点、船舶、货源和分析统计，前端产品化只能看到空表或“测试XXX”，无法判断筛选、图表、地图、穿透是否合理。

第 2 轮组件基建完成后，再进入分析模块重构。分析页需要 MetricCard、ChartCard、MapPanel、RankingList、DrilldownTable 等组件支撑，先建组件能减少第 4-8 轮重复代码和视觉漂移。

第 4 轮分析模块优先于货源、船舶、航线深改，因为分析是平台产品门面，也是验证 seed、地图、图表、聚合接口质量的最快路径。
